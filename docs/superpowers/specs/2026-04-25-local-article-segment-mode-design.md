# 本地文章换段模式设计

## 背景

当前应用已有两套文章来源和翻页路径：

- 文来文章通过 `ArticleFetcher` 和 `articleCache` 请求上一段/下一段，并由 `Config["文来换段模式"]` 控制打完后自动或手动换段。
- 本地文章通过 `ArticleManager` 管理当前文章、段长、进度和上一段/下一段，目前打完后总是自动调用 `NextAndSendArticle` 进入下一段。

用户希望本地文章也支持类似文来的自动/手动换段，但必须维护好状态管理，避免处于本地文章状态时翻下一页却调用文来的 API 翻页。

## 目标

1. 本地文章新增独立的自动/手动换段模式。
2. 模式入口放在本地文章管理器，不放在全局设置页。
3. 本地文章状态下手动翻页只走 `ArticleManager`，不能因为文来缓存存在而调用 `LoadNextSegment` 或 `LoadPreviousSegment`。
4. 文来现有换段模式和翻页行为保持不变。
5. 用户切换为手动模式时给出明确提示，说明可用的翻页方式。

## 非目标

- 不合并文来和本地文章的换段配置。
- 不重构文来获取、缓存或难度计算逻辑。
- 不改变本地文章的分段算法、过滤逻辑、文章进度保存逻辑。
- 不调整主窗口整体布局和快捷键定义。

## 方案

采用独立配置方案。新增 `本地文章换段模式`，值为 `自动` 或 `手动`。默认值为 `自动`，以保持现有行为。

该配置属于本地文章模块，存储在 `ArticleConfig` 中，而不是全局 `Config`。`ArticleManager` 暴露读取和写入该配置的属性，主窗口完成本地文章时只读取本地文章自己的模式，文来完成时仍只读取 `Config["文来换段模式"]`。

## 界面

在 `WinArticle` 本地文章管理器中增加“换段模式”控件，选项为：

- `自动`
- `手动`

窗口初始化时读取 `ArticleManager` 的本地文章换段模式并设置选中项。用户切换时立即保存。

当用户切换到 `手动` 时显示提示：

> 本地文章手动换段模式：打完当前段后不会自动发送下一段。可按 Ctrl+P 发下一段，Ctrl+O 发上一段，也可以点击底部 < / > 按钮翻页。

提示只在用户主动切换到手动时出现。窗口加载时如果配置已是手动，不弹提示，避免每次打开窗口打扰用户。

## 状态管理

翻页分派不能把“文来缓存是否存在”当作“当前是否处于文来模式”。`articleCache.HasArticle()` 只能说明曾经加载过文来文章，不能决定当前翻页来源。

状态规则：

1. 当前来源为 `TxtSource.book` 时，自动换段、`Ctrl+P`、`Ctrl+O` 和主窗口 `< / >` 按钮都只走 `ArticleManager`。
2. 当前来源为 `TxtSource.articlesender` 时，`Ctrl+P` 和 `Ctrl+O` 才允许走文来 `LoadNextSegment` / `LoadPreviousSegment`。
3. 错字重打或慢字重打会以 `TxtSource.unchange` 加载重打内容。完成重打后的后续动作继续使用 `StopHelper` 开始时保存的原始来源 `savedTxtSource` 判断。
4. 本地文章自动/手动只读取 `本地文章换段模式`。
5. 文来自动/手动只读取 `文来换段模式`。

## 行为流程

### 本地文章打完当前段

`StopHelper` 进入本地文章分支时读取 `ArticleManager` 的本地文章换段模式。

自动模式：

- 保持现状。
- 无需错字/慢字重打或重打完成后，继续调用 `NextAndSendArticle(result)` 或 `NextAndSendArticle()`。
- 发送成绩和下一段的行为保持不变。

手动模式：

- 不调用 `NextAndSendArticle`。
- 如果 `自动发送成绩` 开启，则只发送或复制成绩。
- 不加载下一段，保持当前完成状态，等待用户手动翻页。
- 错字/慢字重打流程仍按现有规则先进入重打；重打完成后再按手动模式决定不自动翻页。

### 手动翻页

`Ctrl+P`：

- 当前来源是 `TxtSource.articlesender` 且文来缓存有效时，调用 `LoadNextSegment()`。
- 当前来源是 `TxtSource.book` 时，调用 `ArticleManager.NextSection()` 后执行 `SendArticle()`。
- 其他来源下保留现有兜底行为或不做文来 API 翻页。

`Ctrl+O`：

- 当前来源是 `TxtSource.articlesender` 且文来缓存有效时，调用 `LoadPreviousSegment()`。
- 当前来源是 `TxtSource.book` 时，调用 `ArticleManager.PrevSection()` 后执行 `SendArticle()`。
- 其他来源下保留现有兜底行为或不做文来 API 翻页。

主窗口 `< / >` 按钮继续直接使用本地文章翻页逻辑，不参与文来 API 翻页。

## 错误处理

- 没有选择本地文章时，`ArticleManager` 保持现有空内容返回行为。
- 到文章末尾时，自动模式保持现有只发送成绩、不加载空内容的行为。
- 本地文章当前状态下即使 `articleCache.HasArticle()` 为真，也不得使用文来缓存参数请求上下段。
- 文来当前状态下如果没有有效缓存，保留现有“请先加载文章”的提示。

## 测试

手动验证：

1. 本地文章模式为 `自动`，打完当前段后仍自动进入下一段并发送内容。
2. 本地文章模式为 `手动`，打完当前段后只发送或复制成绩，不自动翻页。
3. 先加载文来，再加载本地文章；本地文章状态下按 `Ctrl+P`，只翻本地文章，不请求文来下一段。
4. 先加载文来，再加载本地文章；本地文章状态下按 `Ctrl+O`，只翻本地文章，不请求文来上一段。
5. 文来状态下按 `Ctrl+P` / `Ctrl+O`，仍正常调用文来上下段接口。
6. 本地文章开启错字重打或慢字重打时，首打进入重打；重打完成后按本地文章换段模式决定是否自动翻页。
7. 重启应用后，本地文章管理器恢复上次保存的 `本地文章换段模式`。

可选代码级验证：

- 为 `ArticleManager` 的模式属性增加轻量测试或手动断点验证，确认默认值、写入和读取都使用 `ArticleConfig`。
- 在快捷键分派处用日志或断点验证，`TxtSource.book` 时不会进入 `LoadNextSegment` / `LoadPreviousSegment`。
