# 详细字数统计设计

## 背景

成绩栏现在显示“今日字数”和“总字数”。总字数来自 `CounterLog`，统计方式是按实际上屏输入累计：

- 普通输入在 `TbxInput_TextChanged` 中按新增字符数写入 `CounterLog.Buffer[0]`。
- 字帖和临摹模式在各自输入处理里按输入文本元素数写入 `CounterLog.Buffer[0]`。
- 成绩栏刷新或程序退出时，`CounterLog.Buffer[0]` 写回 `统计.txt` 的 `字数`。

因此新的详细统计必须和这个记账时机一致，不能只在完成一段、完成一组或保存成绩时统计。否则晴练单半段、重打、中途退出、剪贴板载文等场景会让详细分类合计和总字数不一致。

## 目标行为

1. 成绩栏“总字数”右键打开隐藏的详细字数统计入口。
2. 详细统计展示两个维度：
   - 分类维度：按来源和具体项目统计字数。
   - 难度维度：按 `淼 / 水 / 易 / 普 / 难 / 虐` 六档统计非练单文本字数。
3. 分类维度所有字数相加必须等于成绩栏总字数。
4. 每个统计项显示开始统计年月日。
5. 首次启动新版时，把旧版已有总字数整体迁入“历史数据”。从迁移完成后开始，新增输入才进入细分项。
6. 晴练单统计按实际输入字数实时累计，不能等完整组完成后才统计。

## 非目标

- 不回填旧版已有的文来、本地文章、晴练单日志到新细分项。
- 不改变现有 `统计.txt` 的总字数口径。
- 不改变现有 `ArticleLog`、`WenlaiLog`、`TrainerLog` 的成绩统计窗口逻辑。
- 不把晴练单纳入难度维度。

## 数据模型

新增独立的详细字数统计存储，建议文件名为 `详细字数统计.json`，放在程序数据同级目录。它只负责字数细分，不替代现有总字数统计。

数据结构包含：

- `SchemaVersion`
- `MigratedLegacyTotalWords`
- `MigrationDate`
- `CategoryItems`
- `DifficultyItems`

每个统计项保存：

- `Dimension`：`Category` 或 `Difficulty`
- `Key`：稳定键，例如 `category:wenlai:普`、`category:trainer:1.前500`、`difficulty:普`
- `DisplayName`：界面显示名称。
- `Words`：累计字数。
- `StartDate`：首次开始统计日期，格式 `yyyy-MM-dd`。
- `LastUpdateTime`：最后更新的本地时间。

## 启动迁移

程序启动时执行一次迁移：

1. 读取 `统计.txt` 中现有总字数。
2. 如果新统计文件不存在或未标记迁移完成：
   - 创建分类项 `历史数据`。
   - `历史数据.Words = 现有总字数`。
   - `历史数据.StartDate = 当天日期`。
   - 标记 `MigratedLegacyTotalWords = true`。
3. 后续启动不重复迁移。

迁移后，分类维度的基础总和从“历史数据”开始，之后所有新增输入都进入具体分类项。这样不需要猜测旧记录来源，用户看到的口径清晰。

## 统计上下文

加载文本时建立当前统计上下文。上下文至少包含：

- `TxtSource`
- 分类键和显示名
- 是否参与难度维度
- 难度档位键和显示名

分类映射：

- `TxtSource.articlesender`：`文来 / <文来难度>`；难度使用当前加载文本的本地六档。
- `TxtSource.book`：`本地文章 / <书名>`；难度使用当前加载文本的本地六档。
- `TxtSource.trainer`：`晴练单 / <练单项>`；不进入难度维度。
- `TxtSource.jbs`：`赛文 / 锦标赛`；难度使用当前加载文本的本地六档。
- `TxtSource.jisucup`：`赛文 / 极速杯`；难度使用当前加载文本的本地六档。
- `TxtSource.raceApi`：优先用当前赛文名或服务器名，退化为 `赛文 / 赛文API`；难度使用当前加载文本的本地六档。
- `TxtSource.clipboard`：`剪贴板载文`；难度使用当前加载文本的本地六档。
- `TxtSource.qq`：`QQ群载文`；难度使用当前加载文本的本地六档。
- 其他来源：`其他来源`；难度使用当前加载文本的本地六档。

文来分类维度用文来服务端难度标签；难度维度仍统一使用本地六档，保证两个维度含义不同：

- 分类维度回答“这批字来自哪里”。
- 难度维度回答“非练单文本按本地难度分布在哪里”。

## 记账时机

新增一个集中 helper，例如 `DetailedWordCountLog.AddTypedWords(int words, TypingWordCountContext context)`。

所有当前写入 `CounterLog.Buffer[0]` 的位置，都同时调用这个 helper：

- 普通输入 `TbxInput_TextChanged`
- 字帖模式输入处理
- 临摹模式输入处理

helper 行为：

1. `words <= 0` 时不处理。
2. 找到或创建分类统计项并增加 `words`。
3. 如果上下文允许难度统计，则找到或创建六档难度项并增加 `words`。
4. 新项的 `StartDate` 设为当天日期。
5. 异步或防抖落盘，避免每次上屏都频繁写文件。

为了保持“分类合计 = 总字数”，详细统计只以分类维度参与总数校验。难度维度排除晴练单，不要求等于总字数。

## 统计界面

入口：

- 在成绩栏文本框上增加右键菜单项“详细字数统计”。
- 点击打开新的统计窗口。

窗口采用单页总览，不使用 Tab。信息量不大，打开后应一眼看到全部分布。

布局：

- 顶部标题栏：`详细字数统计`，右侧保留刷新和关闭按钮。
- 顶部摘要带：
  - `总字数`
  - `分类合计`
  - `难度统计字数`（不含晴练单）
  - `开始统计日期`
  - 一致性状态：一致时显示 `已对齐`；不一致时显示差额。
- 主内容区左右两列：
  - 左侧宽列：`分类统计`，展示来源维度。
  - 右侧窄列：`难度分布`，展示 `淼 / 水 / 易 / 普 / 难 / 虐` 六档。
- 底部状态栏：
  - 显示最后更新时间。
  - 需要校准时显示简短提示，例如 `已将差额补入历史数据`。

视觉风格：

- 延续现有主题色、字体色和按钮色。
- 使用清晰的分组标题和细边框，不做大块营销式卡片。
- 分类统计上方用饼图展示主要来源占比，下方用表格展示明细，列为 `项目`、`字数`、`占比`、`开始统计日期`。
- 难度分布上方用横向柱状图展示六档字数，下方用六行固定顺序列表显示难度名、字数、占比和开始统计日期。
- 分类行可按来源分组显示：`历史`、`文来`、`本地文章`、`晴练单`、`赛文`、`其他`，避免长列表杂乱。

图表实现：

- 使用 `LiveChartsCore.SkiaSharpView.WPF`（LiveCharts2）。它的 NuGet 包支持 `.NET Framework 4.6.2`，本项目 `.NET Framework 4.8` 可以使用；视觉、动画和交互比传统 WPF 图表更适合这个统计面板。
- 分类占比使用饼图或环形图。项目过多时只展示前 8 项，其余合并为 `其他`，明细表仍显示完整列表。
- 难度分布使用横向柱状图，固定六档顺序。
- 图表颜色从当前主题派生，避免和窗口主题割裂。
- 不做多套图表降级实现。若用户本地因依赖缺失导致图表显示异常，界面提示需要全量更新。

排序：

- 分类统计默认按字数倒序，`历史数据`可固定在第一行或按字数参与排序。
- 难度统计按六档固定顺序：`淼 / 水 / 易 / 普 / 难 / 虐`。

## 一致性策略

正常情况下，启动迁移加输入时同步记账能保证分类合计等于总字数。

仍需处理异常：

- 程序崩溃时 `CounterLog.Buffer[0]` 和详细统计文件其中一方可能未落盘。
- 用户手动编辑或删除文件。
- 旧版本回退后继续使用，再升级回来。

策略：

1. 打开详细统计窗口时读取总字数和分类合计。
2. 如果分类合计小于总字数，把差额补到 `历史数据`，并更新 `LastUpdateTime`。
3. 如果分类合计大于总字数，显示警告，不自动扣减用户已有分类；提供“按总字数重置历史数据差额”的后续处理空间。

## 测试

优先添加可独立运行的 C# 单元测试，覆盖纯逻辑：

- 首次迁移把旧总字数全部放入 `历史数据`。
- 迁移只执行一次。
- 输入文来文本时同时增加 `文来 / <难度>` 和本地六档难度。
- 输入本地文章时增加 `本地文章 / <书名>` 和本地六档难度。
- 输入晴练单时只增加 `晴练单 / <项>`，不增加难度维度。
- 分类合计等于旧总字数加新增输入字数。
- 新统计项记录开始统计日期。
- 分类图表模型只取前 8 项并合并剩余项为 `其他`。
- 难度柱状图模型按 `淼 / 水 / 易 / 普 / 难 / 虐` 固定顺序输出。

再添加轻量静态 PowerShell 回归测试：

- `TbxInput_TextChanged` 中 `CounterLog.Buffer[0]` 增加处同步调用详细统计 helper。
- 字帖和临摹模式的输入记账处同步调用详细统计 helper。
- 成绩栏 `TbxResults` 有详细统计右键入口。
- 项目文件引用选定图表库，并包含详细统计窗口 XAML。

## 风险

- 现有输入路径分散，遗漏任何 `CounterLog.Buffer[0]` 增加点都会造成新旧统计不一致。
- 详细统计不能在每个输入事件同步写磁盘，否则可能影响输入流畅度。
- `raceApi` 当前可用的赛文名/服务器名需要从现有状态或服务器管理器获取，拿不到时必须稳定退化到 `赛文 / 赛文API`。
- 文来服务端难度标签缺失时应归到 `文来 / 未分类`，但难度维度仍可用本地六档。
- 新增图表依赖会增加包体积和构建变量；发布时必须确保全量更新包包含 LiveCharts2 及其依赖。若用户覆盖更新不完整导致图表加载失败，提示用户执行全量更新。
